# Подготовка GALLERY BRIDGE 1.0.0

## P0. Выпуск и сохранность данных

- На Signed Preview проверять переход с опубликованной APK по манифесту канала. Код новой версии должен быть больше кода установленной базы. Пакет и сертификат остаются прежними при переходе на 1.0.0.
- Проверить встроенное обновление на телефоне, включая отказ в разрешении установки, повтор и сохранение данных. Разделить проверку системного установщика и автоматическую проверку доступности версии.
- Проверить восстановление после прерывания между началом записи и фиксацией результата. Состояние с неясным результатом требует проверки без автоматической перезаписи облачного файла.

## P1. Передача и каталог

- Пройти контрольные сценарии Android SAF и Mail WebDAV из матрицы тестирования. Сверить результат по источнику, провайдеру и облаку с указанием уровня подтверждения.
- Проверить экспорт и импорт резервной копии, повторный импорт, дубликаты, большие списки и остановленное сканирование. При ручных правках проверять сохранение приоритета метаданных.
- Вынести отдельный сценарий из MainActivity после появления регрессионного теста. Начать с координации передачи и восстановления очереди.

## P2. Интерфейс

- Проверить на телефоне каталоги, навигацию, «Назад», прокрутку и выделение, поиск, фильтры, мозаику, масштабирование, повтор загрузки изображения, очередь, историю и настройки в обеих темах.
- Исправлять обнаруженные дефекты по одному. После перехода в RC ограничить изменения исправлениями и проверками.

## Приведение main в актуальное состояние

1. Сверить HEAD, PR, права и настройки защиты main. На контрольной точке аудита main содержит 0.18.0 и является предком рабочей ветки.
2. Подготовить отдельный PR с проверками. Старый workflow main публикует debug-APK. При прямом переносе workflow Preview в main задание публикации ожидает `app-debug.apk`, тогда как загружается `app-release.apk`. Сначала согласовать схему и сделать main веткой сборки и тестирования без автоматической публичной выкладки APK.
3. Проверить PR на целевом SHA, отдельно убедиться в сохранении пакета, сертификата, триггеров Signed Preview и адреса обновлений.
4. После явного согласования интегрировать изменения без force push, повторно сверить рабочую ветку, оба workflow и текущий манифест Preview.

Stable выпускается после прохождения обязательных автоматических и телефонных сценариев. См. [матрицу тестирования](TESTING.md).
